# v0.4 Audio Feasibility — AEC & Speaker Verification

## Playback detection
Already implemented via `NowPlaying.status()` (used in `drainSegments` for
media suppression). Exposed as `playback_detected` / `audio_accepted` /
`audio_rejected` events in `VoiceEventLogger`.

## Acoustic Echo Cancellation (AEC)
- macOS does not expose system-output as a reference signal to third-party
  apps via public API without a virtual audio device.
- Implementing true AEC (NLMS/subband) requires synchronized capture of
  system output + mic input on the same clock; not available with the current
  `MicMonitor`/`AVAudioEngine` tap.
- **Decision:** Not implemented. Playback-aware gating (existing) remains the
  conservative fallback. A virtual-audio-device or CoreAudio aggregate-device
  approach is a future milestone.

## Speaker verification
- No local speaker-embedding model is bundled; adding one (e.g. ECAPA-TDNN)
  would require ~50 MB model + enrollment flow + threshold tuning.
- **Decision:** Deferred. VAD + playback gating + TranscriptSanitizer provide
  the current reliability floor. Speaker verification is a future milestone.

## Raw audio preservation
- `MicMonitor` captures raw 16 kHz mono PCM; segments are passed to
  `WhisperTranscriber` without destructive preprocessing. Raw audio is
  available for diagnostics via `audioDuration` and segment samples.

## Stage B1 — Native system audio capture (implemented)
- `ReflexCore/Sources/ReflexCore/SystemAudioCapture.swift` — Core Audio process tap (macOS 14.2+).
- Private, unmuted stereo-global tap → private aggregate device → IO proc → 16 kHz mono Float32.
- Requires `NSAudioCaptureUsageDescription` (added to project.yml).
- No virtual audio driver required.

## Stage B2 — WebRTC APM (not yet implemented)
- Requires adding WebRTC APM (C++ library) + Objective-C++ bridge.
- Recommended: use a prebuilt WebRTC APM static library or the `webrtc-audio-processing` package.
- Once available, feed `SystemAudioCapture` output as the render (reverse) stream and
  `MicMonitor` output as the capture stream to APM's `ProcessStream` / `ProcessReverseStream`.
- AEC and NS independently configurable.

## Stage B3/B4 — AEC + NS
- Pending WebRTC APM integration. SystemAudioCapture provides the reference stream.
