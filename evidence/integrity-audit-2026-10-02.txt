DEFECT 4 — build-and-verify.sh's model gate is accidental [warn]
-----------------------------------------------------------------
files/build-and-verify.sh:64-68

    "$CLI" --verify 2>&1 | tee "$LOG_DIR/verify-models.log"
    "${PIPESTATUS[0]:-0}" >/dev/null 2>&1 || true

The intended check is dead code. It writes a status to stdout,
redirects it to /dev/null, and swallows any error with `|| true`.
The gate only fires because `set -o pipefail` aborts first — I
confirmed this by reproducing the construct in isolation. So the
script does fail correctly today, but by accident, and the author
clearly did not intend it.

This matters because D3 exists precisely because `--verify` used to
silently pass. A gate that works by accident is the same failure mode
one edit away from recurring.

Fix: drop the PIPESTATUS line entirely and rely on pipefail, or write
it properly:
    if ! "$CLI" --verify 2>&1 | tee "$LOG_DIR/verify-models.log"; then
      fail "model verification (see $LOG_DIR/verify-models.log)"
    fi
